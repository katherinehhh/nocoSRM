# 在界面配置邮件服务

管理员打开「系统配置 → 邮件服务配置」，或访问 http://127.0.0.1:13001/main/mail-services。邮件账户页也提供管理员配置入口。

- Gmail：填写外部 OAuth 应用的客户端 ID、客户端密钥。
- Microsoft 365：填写客户端 ID、客户端密钥和租户；默认租户为 common，按实际组织要求填写。
- IMAP/SMTP：填写收件、发件服务器地址、端口及 TLS 选项。界面初始填入993/465及连接时立即使用TLS；以邮箱服务商给出的实际参数为准，STARTTLS服务须按其要求配置。

首次点击「保存并启用配置」。已有服务商修改参数后点击「保存」，其启用状态保持不变。已有客户端密钥不会返回前端，编辑时留空保留原值。填写新密钥会替换原值。

OAuth 的客户端 ID 和密钥不是邮箱地址或邮箱密码。页面显示完整授权回调地址，请在外部 OAuth 应用登记一致的地址。保存本地配置后即时生效，不必重启；真实授权、服务商许可和邮件投递仍须实际验证。

点击「连接邮箱账户」，选择已配置服务商。Gmail/Microsoft完成外部授权；IMAP/SMTP在账户连接界面填写邮箱、用户名及授权密码。选择首次同步日期后开始同步，可在原生邮件页面查看同步日志。不要在聊天里发送密钥或邮箱授权密码。

已配置服务商可单独启用或停用。停用需要确认，已有账户将不可用于收发和同步，历史邮件仍保留；恢复启用后可继续使用。服务商实例名固定，避免破坏已有账户关联。

仅有管理员权限的身份可读取或修改服务商配置，普通业务账号无法调用配置接口。密钥保存在服务器本机私有配置文件，权限0600，未承诺数据库或磁盘层加密，不应提交到Git或共享给客户。部署配置中其他服务商及参数保留；本页面不管理邮件审批通知的SMTP通道。

当前按本地单实例验证。配置写入使用版本校验和文件锁；冲突时保留填写内容，核对新配置后再保存。保存后若服务配置重新加载失败，将恢复之前文件并返回失败提示。未配置真实邮箱时，不能把本地配置验证当作收发邮件成功。
