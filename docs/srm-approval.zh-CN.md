# SRM 原生定标审批

询价定标已接入 `@nocobase/app-plugin-approval`，采用“采购负责人 → 部门负责人”两级审批。只在最终通过时创建一张关联采购订单草稿；第一审、退回、驳回均不创建订单。已有历史单据保持原流程。

## 配置

管理员进入 [业务配置](http://127.0.0.1:13001/main/operationsSettings)，在“定标审批”卡片选择两位不同的现有审批人，勾选启用并保存。申请人不能审批自己的定标，供应商不能读取内部审批意见。审批人停用、失去资格或下一审无人可处理时，服务端拒绝操作，不跳过审批。修改配置仅影响下一次新提交；已提交的单据保留提交时的人员。

当前启用人员：采购负责人“客户演示 · 审批员”，部门负责人“【演示】财务审批”。没有新增账号、调整角色或重置密码。若这不是实际组织职责，请在配置页选择本组织人员。

## 给客户演示

1. 采购员新建并发布询价，两家供应商提交报价。
2. 采购员评审报价，可使用 AI 生成建议；人工选择报价并提交定标。
3. 采购负责人登录，从业务工作台进入单据，查看报价、AI 理由和审批进度，填写意见并通过。展示状态转为“部门负责人审批”，仍无订单。
4. 部门负责人登录，同一单据填写意见并通过。展示两位不同人员的审批记录及关联采购订单草稿。
5. 采购端继续订单提交、供应商确认、收货、质检和入库；收货合格金额可沿现有接口同步至独立财务应用。
6. 用另一张询价展示退回：填写修改理由，回到报价评审重新提交；旧意见保留，新提交生成新的审批任务。驳回也需填写理由。

审批任务发送站内通知并进入业务工作台；没有配置外部邮件发送。意见必填，页面异常保留输入。重复提交同一决策不会重复投票或创建订单。单据变更导致审批内容过期时，刷新后重新核对再提交。
