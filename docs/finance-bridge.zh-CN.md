# SRM 与财务对账平台联动演示

两套应用保持独立，通过签名 API 双向同步，以单据链接追溯来源。SRM 负责采购、供应商交货和收货过账；财务平台负责收货对账、依据补充、差异确认、独立审批和结算结果回写。

## 已跑通的案例

- 采购及合格收货：10件，单价100元，税率13%。
- 原始和结算未税金额1000元，税额130元，含税金额1130元。
- 财务草稿由正式收货自动生成，`demo=false`；这仍是客户演示业务数据，不代表客户实际业务。
- 已实际调用两边 HTTP API 完成审批与结果回写，库存保持10件。
- [SRM 台账](http://127.0.0.1:13001/main/business-ledger/7aeeca02-f771-4690-a86d-b34b98a54ba8)
- [财务对账单](http://localhost:13002/main/finance/7242a4df-78a5-4f4c-8101-d419a973de8a)
- [采购订单](http://127.0.0.1:13001/main/supply/orders/278f5538-450f-4508-84a9-83e90905fdd9)
- [收货单](http://127.0.0.1:13001/main/supply/receipts/b065195d-2bc1-4785-bf16-a9e431494512)

## 五分钟展示现有结果

1. 在 SRM 打开采购订单和收货单，展示独立审批、合格数量与过账记录。
2. 打开 SRM 台账的“财务对账”卡片，展示原始收货金额、财务结算金额、状态、收货行和同步时间。
3. 点击“查看财务单据”，进入财务平台。第一次需要独立登录；单据链接不包含密码或 API 密钥。
4. 展示对账单来源快照和操作历史：对账 → 补充依据 → 确认差异 → 提交审批 → 独立审批 → 回写。
5. 展示真实 SRM 执行记录，再点击“采购订单”或“收货单”追溯来源，返回 SRM 刷新确认“回写完成”。

现有单据已经完成，不能再次作为草稿操作。现场展示点击过程时请使用下面的新单据流程，不删除历史或改回状态。

## 现场跑一次新流程

1. SRM 采购员使用“客户演示 · 现场新建采购流程”草稿，提交采购审批；审批员审批，供应商确认订单。
2. 采购员建立对应交货计划，完成交货审批；供应商发运，仓储员完成交货并创建正式收货单、过账。
3. 等待约15秒，在财务平台刷新列表，找到对应 `SRM-收货单号-行标识` 的草稿。每个收货行生成一个独立对账单。
4. 财务员点“对账”；采购员补充依据，写明收货/签收凭证；财务员确认差异并提交审批。
5. 审批员独立审批。提交人不能审批自己的单据；来源已变化时需要先核对来源，不允许带着旧快照结算。
6. 财务员点击回写。此时等待后台真实接口确认，正常约15～30秒；刷新后财务单据完成，SRM 卡片同步显示结算结果。断线时保留待回写状态并自动重试。

此处“回写完成”表示 SRM 已确认结算结果，没有连接银行付款、ERP凭证过账或税务开票服务。原有模拟演示单据仍明确标记为模拟。

## 演示身份

SRM 身份见 [采购交货演示说明](customer-demo.zh-CN.md)。财务平台使用三个限定权限账号：

| 身份 | 邮箱                                     | 操作                           |
| ---- | ---------------------------------------- | ------------------------------ |
| 采购 | bridge-procurement@customer-demo.invalid | 补充依据                       |
| 财务 | bridge-finance@customer-demo.invalid     | 对账、确认差异、提交审批、回写 |
| 审批 | bridge-approver@customer-demo.invalid    | 独立审批                       |

密码仅保存在本机 `app2/storage/bridge-demo/accounts.json`，权限0600；未写入聊天或版本库。两个应用独立登录，切换身份需退出重登，可使用不同浏览器配置文件。

## 同步范围与运维

- 当前支持组织 main、人民币、正整数合格收货数量。零数量、小数数量或超过安全金额范围的来源会显示明确失败，修正来源后恢复同步；不会悄悄舍入数量。
- 来源以收货单和行标识稳定去重。来源版本与财务状态版本分开管理，重复、过期、改写请求受校验。
- 财务已提交审批、已审批或已完成后，不自动覆盖变化的来源，需人工核对处理；不要直接修改数据库或重置状态。
- 两边使用原生配置、数据库事务、生命周期和15秒调度。收货入口读取已过账的正式单据，不导出历史 `demo=true` 数据。台账的外部签收回执与财务结果分别保留，不相互冒充。
- 接口配置在两边 `financeBridge`，或使用 `SRM_FINANCE_BRIDGE_ENABLED`、`SRM_FINANCE_BRIDGE_SECRET`、`SRM_BRIDGE_BASE_URL`、`FINANCE_BRIDGE_BASE_URL` 环境变量。启用需两边同一至少32字符的专用签名密钥。保留应用原生 API Key 供其他受权限控制的集成使用，本链路的签名密钥独立配置。
- 地址包含应用路径 `/main`；远程部署使用 HTTPS。改变地址或密钥需同步更新两边并重启。禁止在 URL 中携带密钥。
- 当前为本地单进程环境；多实例部署前应配置共享调度/队列并完成并发验证。
- 部署前备份保存在两边 `storage/finance-bridge/pre-connect*`。联调报告在 `app1/storage/finance-bridge/live-result.json`。后端与构建已验证；浏览器安全策略限制了本次自动视觉检查，窄屏、深色及焦点尚未验证。
- 运维检查发现财务集成迁移在开发进程提前执行后出现源文件校验警告。已检查实际字段、默认值及旧单据金额与当前迁移一致，未重放迁移或手改历史表；原有 SRM 历史 seed 校验警告也保留。后续发布前应统一迁移执行版本并审查校验记录。
